# Open source project maintenance guidelines

This document provides essential guidelines for maintainers of Siradel's open source projects to ensure effective community management and project sustainability.

*These guidelines should be adapted based on project size, complexity, and community engagement levels. Regular review and updates are recommended to reflect evolving best practices.*

## Core Principles

### Shared responsibility
- **Avoid solo maintenance**: If possible, don't maintain a project alone.
- Establish a team of at least 2-3 active maintainers.
- Document maintenance procedures to enable knowledge transfer.

### Team availability
- Aim to respond to issues and PRs within 48 hours.
- When taking extended leave, ensure other active contributors remain available.
- Designate backup maintainers for critical periods.
- Use "out of office" status on GitHub when unavailable.

## Issue and Pull Request management

### Issue management
- If GitHub issues serve as your project backlog and you accept contributions, provide clear and detailed issue descriptions.
- Assign issues to team members when work begins internally to provide transparency to the community.
- Use consistent labels to categorize issues (bug, enhancement, help wanted, good first issue, etc.).
- Review and categorize new issues promptly.

### Pull Request guidelines
- Always be constructive when reviewing tickets and pull requests.
- Do not hesitate to reject contributions that don't meet project standards or goals, but do so respectfully and with clear explanations.
- When refusing contributions, explain why clearly:
  - Out of scope for the project.
  - Already being worked on internally.
  - Too ambitious or complex for current project goals.
  - Requires prior discussion before implementation.
  - Doesn't align with project architecture or standards.
- Close old, non-applicable, or stale pull requests that haven't been updated for a reasonable period.
- Engage with contributors to help improve their submissions when possible.

## Community standards

### Code of conduct
- Respect and enforce the code of conduct - this applies to maintainers, not just external contributors.
- Maintain professional, respectful, and inclusive communication at all times.
- Address violations promptly and fairly.

### Contribution standards
- Maintain up-to-date CONTRIBUTING.md file and associated documentation.
- Establish and communicate clear criteria for accepting contributions.
- Maintain consistent code quality and testing standards.
- Ensure contributions include appropriate documentation updates.
- Ensure contributions respect the project's license and intellectual property guidelines.

## Quick Reference Checklist

**Daily/Weekly:**
- [ ] Respond to new issues and PRs within 48 hours.
- [ ] Assign issues when starting work internally.
- [ ] Provide constructive feedback on contributions.

**Monthly:**
- [ ] Review and close stale PRs and issues.

**Quarterly:**
- [ ] Assess project health and maintainer capacity.
- [ ] Review and update contribution guidelines.
